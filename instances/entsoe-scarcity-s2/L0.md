## 3. Raw Response & Multi-Document Merge Rules

1. **Raw Byte Preservation:** Every raw HTTP response payload must be preserved byte-for-byte under `evidence/runs/<RUN_ID>/raw/` before parsing.
2. **Batch Metadata:** Record request URL (token redacted), request timestamp $T_{\text{req}}$, response timestamp $T_{\text{resp}}$, HTTP status code, and SHA-256 digest of raw bytes in `run_metadata.json`.
3. **Multi-Document Payload Handling:** If an XML response contains multiple `Balancing_MarketDocument` elements:
   - Inventory and preserve every document.
   - Verify `documentType = A85` and `<process.processType>A16</process.processType>`.
   - For repeated `mRID` document revisions, identify the numerically latest `revisionNumber` as the current-state document while preserving all received revisions in the inventory.
   - After source-defined revision handling, any remaining collision on the same registered UTC MTU is a duplicate and Target S fails. Zero analyst-discretion deduplication.
