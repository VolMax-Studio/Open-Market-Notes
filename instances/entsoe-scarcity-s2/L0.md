### Shortage Price Category Selector (B-23 & B-24 Resolution)
In IEC 62325 Balancing Market Documents (DocumentType `A85`), price direction is defined at the `<Point>` level by the XML element `<imbalance_Price.category>`:
- **`A04`**: Shortage / Deficit imbalance price (Deficit price paid by balance responsible parties).
- **`A05`**: Surplus / Excess imbalance price.
- **Shortage Category Rule:** For all six zones (`AT`, `BE`, `DK-1`, `DK-2`, `FR`, `NL`), the scarcity evaluation extracts points where `<imbalance_Price.category>A04</imbalance_Price.category>`.
  - In single pricing zones (`AT`, `BE`, `DK-1`, `DK-2`), `A04` and `A05` prices are identical.
  - In dual pricing zones (`FR`, `NL`), `A04` represents the shortage direction.

## 3. Raw Response, Container Extraction & Multi-Period Merge Rules

1. **Raw Byte Preservation:** Every raw HTTP response payload must be preserved byte-for-byte under `evidence/runs/<RUN_ID>/raw/` before any container extraction or parsing.
2. **Batch Metadata:** Record request URL (token redacted), request timestamp $T_{\text{req}}$, response timestamp $T_{\text{resp}}$, HTTP status code, and SHA-256 digest of raw bytes in `run_metadata.json`.
3. **Transport Container & Extraction:**
   - If raw payload starts with PKZip magic bytes (`50 4B 03 04` / `b'PK\x03\x04'`):
     - Open archive in memory using `zipfile.ZipFile`.
     - Process member XML documents in strictly alphabetical filename order (`sorted(zip_ref.namelist())`).
     - Record member metadata (filename, size, member SHA-256) in `document_inventory.json`.
   - If raw payload starts with direct XML (`b'<'`), parse as a single document.
   - If payload is neither valid PKZip nor valid XML, halt with `PAYLOAD_FORMAT_UNEXPECTED`.
4. **Multi-Period Iteration within TimeSeries (B-21 Resolution):**
   - Within each `<TimeSeries>` element, the parser must iterate over **all** child `<Period>` elements (`ts.findall('.//ns:Period')`).
   - For each `<Period>`, extract its specific `timeInterval/start` UTC instant ($T_{\text{period\_start}}$) and resolution (`PT15M`).
   - For each child `<Point>`, compute its timestamp as:
     $$T_{\text{point}} = T_{\text{period\_start}} + 15\text{ min} \times (\text{position} - 1)$$
5. **Document Validation, Revision Handling & Price Filtering (B-23 & B-25 Resolution):**
   - Verify `documentType = A85` and `<process.processType>A16</process.processType>` on all documents.
   - Filter points strictly and unconditionally for `<imbalance_Price.category>A04</imbalance_Price.category>`. Points lacking the category element or carrying any other code (e.g. `A05`) must not enter the shortage price series.
   - For repeated `mRID` document revisions, identify the numerically latest `revisionNumber` as the current-state document while preserving all received revisions in the inventory.
   - After source-defined revision handling, any collision on the same registered UTC MTU with conflicting values or unresolvable duplicates triggers Target S failure.
6. **Offline Vintage Integrity Verification (B-26 Resolution):**
   - In offline interpretation runs (`--source-raw-dir`), verify before parsing that every raw response matches the pinned SHA-256 digest recorded in the source run's metadata (`run_metadata.json` / `outputs.sha256`). Any missing metadata or checksum mismatch triggers an immediate halt with `EXECUTION_STATE_INVALID`.
